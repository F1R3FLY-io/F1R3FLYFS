## Context

PR #40 is a 42k-line, 28-commit overhaul turning F1r3Drive into a cross-platform
(macOS native File Provider/FSEvents + Linux FUSE) blockchain filesystem with
wallet/token access control, tiered caching, and placeholder materialization.
GitHub's API refuses the diff (>20k-line cap), so review used a locally generated
diff partitioned by component. `/multi-review` could not run (diff exceeds the
tool's 100 KB truncation cap); this is a local single-reviewer pass instead.

### Systemic finding (read first)

The PR ships several parallel/duplicate implementations and the CLI wires up only
some of them. `F1r3DriveCli` mounts `app/linux/fuse/F1r3DriveFuse` (line 154) but
never calls its `initialize()/start()/setupPlatformIntegration()`, so the whole
`platform/` ChangeWatcher + `placeholder/` + `cache/` machinery is **dead at
runtime** on the main path. This reduces the live severity of many cache/platform
bugs (they cannot fire yet) but is itself a problem: a large body of code is
presented as working while being unreachable. A scope/wiring decision is needed
before "fixing" dead-path bugs is worthwhile.

## Findings (fix order)

Status legend: `todo` | `in_progress` | `fixed` | `wontfix` | `needs-decision`

### Critical — live paths

- [ ] **F1: Auth bypass** — `folders/PhysicalWalletManager.java:225`
  `validatePrivateKey` is a TODO stub returning true for any string >=64 chars.
  Live gate on macOS unlock path (`F1r3DriveCli:866 -> BlockchainFolderIntegration:235 -> unlockPhysicalWallet:92`).
  Fix: implement real key->revAddress derivation check (secp256k1 pubkey -> REV address) and reject mismatches. status: todo

- [ ] **F2: Data loss on shutdown** — `macos/.../F1r3DriveCli.java:120,551`
  `demoFolderPath` defaults to `mountPoint`; `cleanupMountDirectory()` recursively
  deletes its contents on shutdown. Fix: never default demoFolderPath to the mount
  point; require an explicit, dedicated path; refuse to recursively delete a
  non-empty user dir. status: todo

- [ ] **F3: Path traversal** — `folders/PhysicalWalletManager.java:382`, `LockedPhysicalWallet.java:264`
  Wallet read/write/delete use `walletPath.resolve(relativePath)` with no
  containment check; even locked wallets can read other wallets' key files.
  Fix: normalize and assert `resolved.startsWith(walletPath.normalize())` before any IO. status: todo

### High — core FS/blockchain correctness

- [ ] **F4: Shared signing-key zeroing** — `folders/UnlockedPhysicalWallet.java:667`
  `cleanup()` zero-fills the array returned by `getPrivateKey()`, which is the live
  `signingKey()` backing array shared with `BlockchainContext`. Fix: clone before
  zeroing, or don't zero a shared array. status: todo

- [ ] **F5: Directories not recognized** — `filesystem/common/AbstractPath.java:66`
  Concrete `AbstractPath.getAttr` sets no mode bits and shadows
  `Directory.getAttr`'s `S_IFDIR` (Java "class wins over interface default") for
  `RootDirectory`/`BlockchainDirectory`. `TokenDirectory` overrides so is unaffected.
  Fix: make `AbstractPath.getAttr` abstract or have directory classes/AbstractLocalPath
  set S_IFDIR; ensure file classes set S_IFREG. status: todo

- [ ] **F6: Deploy-queue hang** — `filesystem/InMemoryFileSystem.java:947,1080`
  `renameFile`/`unlinkFile` enqueue `atomicRename`/`atomicDelete` in addition to
  `p.rename()`/`p.delete()` (which already enqueue `renameChanel`/`forgetChanel`);
  two Rholang for-comprehensions consume one channel value -> one blocks forever.
  Fix: enqueue exactly one mutation per op. status: todo

- [ ] **F7: Silent data loss on write** — `filesystem/deployable/BlockchainFile.java:148`
  Idempotency check clears `isDirty=false` when bytes at this offset match disk,
  discarding earlier dirty-but-undeployed regions. Fix: track dirty regions, not a
  single offset comparison. status: todo

- [ ] **F8: Cross-dir move loses file** — `filesystem/InMemoryFileSystem.java:960`
  `atomicRename` updates only the old parent's on-chain children list; new parent's
  set never updated -> moved file disappears on remount. Fix: update both parents. status: todo

- [ ] **F9: pendingDeletions never cleared** — `filesystem/InMemoryFileSystem.java:1005`
  Added to but never removed; deleting a path permanently blocks recreating it.
  Fix: remove from set once the deletion deploy completes (or on recreate). status: todo

- [ ] **F10: Large writes throw** — `rholang/RholangExpressionConstructor.java:215`
  New 2 MB guard contradicts `BlockchainFile.MAX_FILE_CHUNK_SIZE = 160 MB`; chunks
  2-160 MB throw. Fix: reconcile the two limits (single source of truth). status: todo
